Discovering Excessive Data Exposure
After getting the API documentation, our next step is to use the documentation to authenticate to the target API and begin forming requests.
1. Review
	When reviewing the documentation, take a look at the different types of requests, the endpoints that are out there, and get an understanding of how the functionality works.
2. Use postman to send out requeests.
3. Look for excessive data exposures in the response.
	Excessive data exposure occurs when an API provider sends back a full data object typically depending on the client to filter out the information they need.




Perform Baseline Vulnerability Scanning
When vulnerability scans are applied generically to web APIs, the most common outcome is to recieve false negative results(not detecting or reporting existing vulns). Also most security scanners can only discover security misconfigurations.
Configure your OWASPZAP to throughly scan for security misconfigurations and get the most out of it.
Security misconfigurations include missing system patches, unnecessary features enabled, lack of secure transit encryption, weak security headers, verbose error messages, cross origin resource sharing, and cors policy misconfigurations.

2. OWASP ZAP
	zaproxy
	- Import the openapi specs.yml definition, add correct url, right click to perform active scan.
	- Manual explore, launch HUD, use the web app like an end user, At the top left of the HUD, add your target to the scope of testing. Once you have authenticated to the app and performed a baseline set of actions, perform an active scan. On the right-hand side of the HUD, set the Attack Mode to On. This will begin scanning and performing authenticated testing of the target. Depending on the scale of the web application that you are targeting, this scan could take a while.  From here you should investigate the results. Work through them and determine which are actual findings and which are false positives.
